# Регресс-тест промпта и Skills (eval)

Полная механика и — самое главное — **актуальный список тестовых фикстур** живут в `eval/README.md`. Список со временем растёт (правило роста — см. там же), поэтому при каждом вызове читай `eval/README.md` заново, а не полагайся на то, что помнишь список фикстур из прошлой сессии.

## Как выполнить
1. Прочитай `eval/README.md` целиком.
2. Для **каждой** фикстуры, описанной там (на сегодня их несколько — например основная DEV-фикстура и отдельная LIVE-фикстура свопа номеров, но список может измениться) — прочитай указанный входной файл (`eval/Сайты.eval*.txt`) и проверь сайты из него по обычному алгоритму, как при обычной TQA-проверке. Агентам `qa-eval-*` Шаг 7 п.2 не выполнять (уборку делаешь ты в п.5 после сверки; имена маркеров форм они возвращают в отчёте). Чем гонять (основная сессия или агенты `qa-eval-*`/`tqa-page-agent`, для визуального просмотра Шага 3.3 — `tqa-visual-agent`) — смотри `eval/README.md`; если там не указано, прогоняй основной сессией.
3. Сверь результат с соответствующим разделом `eval/ground-truth.md` — по каждому пункту явно скажи, совпало или нет.
4. Если что-то разошлось с эталоном — это сигнал регрессии в промпте/skill, а не в тестовом сайте: укажи, какой конкретно пункт не совпал и к какому файлу (`CLAUDE.md` или конкретный `SKILL.md`) он привязан, чтобы можно было быстро найти причину (`git log`/`git diff` по этому файлу).
5. После сверки убери служебные файлы прогона по Шагу 7 CLAUDE.md: `.form-submissions/` и `.playwright-cli/`. Папки `projects/{домен}/{прогон}/` фикстур (с `report.md` и `screenshots/`) удаляй только если пользователь явно попросил.

## Важно
- Свой рабочий `Сайты.txt` в этом процессе не участвует и не подменяется.
- Это ручной процесс поддержки промпта — вызывай только по явной просьбе пользователя, никогда не подключай эту логику при обычной проверке сайта клиента.
