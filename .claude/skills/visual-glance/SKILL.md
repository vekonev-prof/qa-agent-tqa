# Визуальный просмотр

`visual-checks` работает по DOM и геометрии и не «видит» страницу. Здесь ты смотришь на неё глазами — по скриншотам — и ищешь только то, что по DOM определить нельзя. Не запускай здесь DOM-проверки (`page-audit`, `eval` для поиска дефектов) — смотри глазами; пересечения с `visual-checks` §1 и `content-checks` §2 допустимы, дубли снимает оркестратор, в одиночном прогоне — сам агент.

## Входные данные
Список URL шаблонов — по одной странице на каждый шаблон из выборки Шага 1 (каждый лендинг — отдельно), готовая рабочая папка прогона `projects/{домен}/{прогон}/` (её передаёт оркестратор), уникальный суффикс сессий; на мультиязычном сайте — ещё и URL второй языковой версии каждого шаблона. Если DEV закрыт паролем — ещё и путь файла авторизации (по умолчанию `.playwright-cli/state-{домен}.json`). Нет чего-то из обязательного в промпте — верни вопрос, а не угадывай. Исключение — одиночный агент, выполняющий шаг сам (CLAUDE.md, Шаг 3.3): `solo` — если суффикс не передан в промпте; рабочая папка и страницы у него уже есть.

**Что читать из CLAUDE.md (подагенту `tqa-visual-agent`; номера строк заголовков — `grep -n '^#' .claude/CLAUDE.md`, дальше Read по диапазону):** только «Шаг 2» (диалоги, баннеры, вход на закрытый DEV), «Шаг 4» (пути, санитизация `{страница}`) и «Критерии для багов» (серьёзность); остальное не нужно. `page-audit.js` в этом skill не запускается.

## Как снять кадры
Для каждого URL и каждого разрешения — 3 кадра: верх страницы, середина, футер. Не больше 9 кадров на шаблон, лишних не делай. После открытия сессии и до первого кадра закрой cookie-баннеры и попапы (как в CLAUDE.md, Шаг 2; при диалоге — `playwright-cli -s=<сессия> dialog-dismiss`), иначе они попадут на все кадры. Просматриваются только три разрешения из таблицы ниже (альбомный 844×390 в просмотр не входит). Язык на мультиязычном сайте — по правилу CLAUDE.md, Шаг 2: десктоп и планшет — основная версия, мобилка — вторая (её URL передаёт оркестратор; одиночный агент находит его сам по правилу Шага 2).

| Разрешение | Открытие сессии |
|---|---|
| Десктоп | `PLAYWRIGHT_MCP_VIEWPORT_SIZE=1920,1080 playwright-cli -s=glance-desktop-<суффикс> open <URL> --browser=chrome` |
| Планшет | `PLAYWRIGHT_MCP_VIEWPORT_SIZE=768,1024 playwright-cli -s=glance-tablet-<суффикс> open <URL> --browser=webkit` |
| Мобилка | `PLAYWRIGHT_MCP_VIEWPORT_SIZE=390,844 playwright-cli -s=glance-mobile-<суффикс> open <URL> --browser=webkit` |

```bash
# верх, середина, низ (после каждого скролла подожди ~1 с — догружаются lazy-картинки)
playwright-cli -s=<сессия> eval "window.scrollTo(0, 0)"
playwright-cli -s=<сессия> screenshot --filename=.playwright-cli/glance/{страница}_{разрешение}_1.png
playwright-cli -s=<сессия> eval "window.scrollTo(0, (document.documentElement.scrollHeight - innerHeight) / 2)"
playwright-cli -s=<сессия> screenshot --filename=.playwright-cli/glance/{страница}_{разрешение}_2.png
playwright-cli -s=<сессия> eval "window.scrollTo(0, document.documentElement.scrollHeight)"
playwright-cli -s=<сессия> screenshot --filename=.playwright-cli/glance/{страница}_{разрешение}_3.png
```
**Если DEV под паролем** — сразу после `open` загрузи авторизацию: `playwright-cli -s=<сессия> state-load <путь>` (путь передаёт оркестратор; по умолчанию `.playwright-cli/state-{домен}.json`) и перезагрузи страницу; без этого на кадрах будет окно входа. Если DEV закрыт окном Basic-авторизации браузера — открывай URL с логином и паролем, см. CLAUDE.md, Шаг 2.

Кадры лежат во временной папке `.playwright-cli/glance/` (не в `projects/{домен}/`). Открой каждый кадр инструментом `Read` (он показывает изображение). Закрой сессию тем же именем в конце.

## Что искать
- [ ] Картинка не загрузилась: пустая рамка, значок битого изображения, видна только подпись `alt`.
- [ ] Картинка искажена: растянута/сплющена (круг выглядит эллипсом, лицо вытянуто), обрезана так, что теряется главное.
- [ ] Текст или кнопка обрезаны (видна только часть надписи), текст выходит за рамку блока.
- [ ] Колонки/карточки выглядят съехавшими: неровные высоты и отступы там, где по логике блоки должны быть в один ряд; лишние огромные пустоты внутри блока (не декоративные разделители).
- [ ] Текст лежит поверх картинки/другого текста и не читается.
- [ ] Sticky-элемент или чат-виджет закрывает контент, кнопку звонка или форму (cookie-баннер сюда не входит — он закрыт до кадров).
- [ ] Мобилка/планшет: горизонтальный скролл страницы, контент выходит за экран, цели тапа слишком близко друг к другу.
- [ ] Шапка и футер на разных шаблонах выглядят по-разному без причины (другой логотип, порядок пунктов, шрифт).

**Не проверяй здесь и не упоминай:** ADA, контраст и доступность (это WAVE/axe), вкусовые оценки дизайна. Если находка совпадёт с находкой page-агента (DOM/`page-audit`) — просто верни её: дубли снимает оркестратор при сборке отчёта (в одиночном прогоне — сам агент, объединяя с находками `visual-checks`/`content-checks`).

## Правило уверенности
- Явный дефект, который виден на кадре без интерпретации, — в основной список с тегом `[Visual]`, серьёзность по «Критериям для багов» CLAUDE.md (раздел «Визуальные»): 🟥 — не загрузившаяся или искажённая картинка, обрезанный текст/CTA, съехавшая сетка, перекрытия, горизонтальный скролл (как «UI/UX-баги»); 🟨 — различия шапки/футера между шаблонами. Находки визуального просмотра с Figma-макетом не сверяются (`figma-compare` для них не вызывается) — только по отдельной просьбе пользователя.
- Если возможно, подтверди подозрение через `eval` (например, `naturalWidth === 0` у картинки, `scrollWidth > clientWidth` у обрезанного элемента) — так находка станет доказуемой.
- Сомнительное («похоже на задумку дизайна», декоративные пустые полосы) — только в «Рекомендации для ручной проверки». Не хеджируй в основном списке.
- Декоративное пустое место (разделитель, отступ между секциями, `aria-hidden`-блок) — не баг.

## Доказательство и уборка
Кадр, на который ссылается находка, скопируй в `projects/{домен}/{прогон}/screenshots/{страница}_bugs/{разрешение}_{проблема}.png` (Шаг 4 CLAUDE.md; при необходимости сначала `mkdir -p`), после копирования удали исходный кадр. Остальные свои кадры из `.playwright-cli/glance/` удали после просмотра (только свои файлы, не саму папку).

## Возвращаемый результат
Список находок: страница, разрешение, что видно на кадре, файл-доказательство, серьёзность. Отдельно — пункты для «Рекомендаций». Если ничего нет — «Визуальный просмотр: дефектов не обнаружено (шаблонов: N, разрешений: 3)». Если какой-то шаблон или разрешение не просмотрены — так и напиши, с причиной.
