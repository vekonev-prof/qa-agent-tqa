# Мультиязычность — метод декларирования

Здесь проверяется не сам перевод (это `content-checks`), а то, ПРАВИЛЬНО ЛИ сайт объявляет поисковикам/браузеру связь между языковыми версиями. Проверяй только на главной и на одной странице каждого шаблона из обычной выборки (Шаг 1 в CLAUDE.md) — не обходи весь сайт ради этого, для site-wide аудита есть отдельные краулер-инструменты (Screaming Frog и подобные), агент делает точечную, а не исчерпывающую проверку.

## Когда вызывать
Только если у сайта есть вторая языковая версия (переключатель языка в UI, hreflang-теги, или URL-паттерн вроде `/es/`) — это уже должно быть определено на Шаге 1/2 выбора страниц (CLAUDE.md). На одноязычном сайте этот скилл вообще не вызывается — не вызывай "на всякий случай".

## Чек-лист
**Проверь все четыре метода (в охвате, описанном ниже), не только один — и явно укажи в отчёте, какие из них реально присутствуют, а какие отсутствуют** (не только общий вывод "мультиязычность работает").

**Охват (CLAUDE.md, Шаг 2 и Шаг 3):** скилл вызывается на главной и на одной странице каждого шаблона. На каждой из этих страниц проверяй `<html lang>` и hreflang в `<head>` на каждой открытой языковой версии (десктоп — основной язык, мобилка — второй): `head.hreflang` из `page-audit` берётся на обеих версиях, иначе взаимность связей (ниже) не проверить. Один раз на сайт (не по страницам, на десктопе): hreflang в sitemap и заголовок `Content-Language`.

**Источник фактов:** `<html lang>` и hreflang из `<head>` бери из page-audit (ключи `page.lang`, `head.hreflang`); отдельный `eval` — только для того, чего там нет, или для перепроверки конкретной находки.
- [ ] `<html lang="...">` — соответствует фактическому языку страницы (`en`, `es` и т.п.), а не захардкожен одинаково на всех версиях.
- [ ] hreflang в `<head>`: `<link rel="alternate" hreflang="...">` — присутствуют для каждой языковой версии (и `x-default`, если используется). Связи двусторонние: каждая версия ссылается и на себя, и на альтернативы. Проверяй по разметке (данные из page-audit, `head.hreflang` обеих открытых языковых версий), без дополнительных переходов. В `head.hreflang` href обрезан до 120 символов, записей не больше 20: если значение выглядит оборванным или языков больше двух — сверь через `eval`. **Переходить по каждому hreflang-URL и проверять, что он отдаёт 200 — не по умолчанию**; делай это точечно только там, где уже есть основание подозревать проблему (например, `visual-checks`/`content-checks` нашёл непереведённый контент на этой странице).
- [ ] hreflang-аннотации в **sitemap** (`<xhtml:link rel="alternate" hreflang="...">` внутри записей `sitemap.xml`/`sitemap_index.xml`) — некоторые сайты декларируют мультиязычность через sitemap вместо (или вместе с) тегов в `<head>`. Проверяй обязательно, не пропускай как необязательное.
- [ ] HTTP-заголовок `Content-Language` — проверь обычным HTTP-запросом, как sitemap на Шаге 1 (например, `curl -sI <URL>`) на главной каждой языковой версии. Обязательный пункт, а не «если удобно» — если технически не можешь посмотреть заголовки конкретно в этом прогоне, так и напиши в отчёте, не пропускай молча.

## Возвращаемый результат
**Итог по каждой странице (для `<html lang>` и hreflang в `<head>`) и один раз на сайт (для hreflang в sitemap и `Content-Language`):** явно перечисли, какой метод(ы) присутствует, какой отсутствует (например: «hreflang в `<head>` есть и корректен; hreflang в sitemap отсутствует; `Content-Language` не проверен — заголовки недоступны в этом прогоне»). Если проблем нет — «Проблем с декларированием мультиязычности не обнаружено».

Находки — `[SEO]`. Серьёзность: 🟥 — на мультиязычном сайте полностью отсутствуют оба метода hreflang (и в `<head>`, и в sitemap) либо взаимные ссылки не совпадают или ведут на код языка, которого на сайте нет; 🟨 — частичная декларация (один метод из двух, не для всех версий/шаблонов) либо неверный или отсутствующий `<html lang>`; 🟩 — отсутствующий или неверный `Content-Language`. `x-default` и не-200 у hreflang-URL уровней не имеют (не находка).
