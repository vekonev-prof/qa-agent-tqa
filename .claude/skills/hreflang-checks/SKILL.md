# Мультиязычность — метод декларирования

Здесь проверяется не сам перевод (это `content-checks`), а то, ПРАВИЛЬНО ЛИ сайт объявляет поисковикам/браузеру связь между языковыми версиями. Проверяй только на страницах из своей обычной выборки (Шаг 1 в CLAUDE.md) — не обходи весь сайт ради этого, для site-wide аудита есть отдельные краулер-инструменты (Screaming Frog и подобные), агент делает точечную, а не исчерпывающую проверку.

## Когда вызывать
Только если у сайта есть вторая языковая версия (переключатель языка в UI, hreflang-теги, или URL-паттерн вроде `/es/`) — это уже должно быть определено на Шаге 1/2 выбора страниц (CLAUDE.md). На одноязычном сайте этот скилл вообще не вызывается — не вызывай "на всякий случай".

## Чек-лист
**Проверь все четыре метода на каждой из проверяемых страниц, не только один — и явно укажи в отчёте, какие из них реально присутствуют, а какие отсутствуют** (не только общий вывод "мультиязычность работает"):
- [ ] `<html lang="...">` — соответствует фактическому языку страницы (`en`, `es` и т.п.), а не захардкожен одинаково на всех версиях.
- [ ] hreflang в `<head>`: `<link rel="alternate" hreflang="...">` — присутствуют для каждой языковой версии (и `x-default`, если используется). Связи двусторонние: каждая версия ссылается и на себя, и на альтернативы. Проверяй по разметке (`eval`), без дополнительных переходов. **Переходить по каждому hreflang-URL и проверять, что он отдаёт 200 — не по умолчанию**; делай это точечно только там, где уже есть основание подозревать проблему (например, `visual-checks`/`content-checks` нашёл непереведённый контент на этой странице).
- [ ] hreflang-аннотации в **sitemap** (`<xhtml:link rel="alternate" hreflang="...">` внутри записей `sitemap.xml`/`sitemap_index.xml`) — некоторые сайты декларируют мультиязычность через sitemap вместо (или вместе с) тегов в `<head>`. Проверяй обязательно, не пропускай как необязательное.
- [ ] HTTP-заголовок `Content-Language` — проверь через доступный способ (например, `playwright-cli request <id>`, если показывает заголовки ответа). Обязательный пункт, а не «если удобно» — если технически не можешь посмотреть заголовки конкретно в этом прогоне, так и напиши в отчёте, не пропускай молча.

## Возвращаемый результат
**Итог по каждой странице:** явно перечисли, какой метод(ы) присутствует, какой отсутствует (например: «hreflang в `<head>` есть и корректен; hreflang в sitemap отсутствует; `Content-Language` не проверен — заголовки недоступны в этом прогоне»). Если проблем нет — «Проблем с декларированием мультиязычности не обнаружено».
