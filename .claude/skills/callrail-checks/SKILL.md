# Проверка CallRail (опционально, только по запросу)

## Условие вызова
Вызывается только если явно запрошено — в `Сайты.txt` (`Комментарии:`) или прямым указанием пользователя. Не входит в стандартный чек-лист и не вызывается автоматически, в отличие от `visual-checks`/`content-checks`/`technical-checks`.

**Имеет смысл только на LIVE.** На DEV свопов не бывает вовсе (см. `technical-checks`, раздел 7) — даже если пользователь попросит эту проверку для DEV-страницы, там нечего искать: сообщи, что на DEV своп технически отсутствует по определению, и не трать вызов впустую.

## Что НЕ входит в эту проверку (принципиально)
- GTM, GA4, Google Ads Enhanced Conversions, любые другие маркетинг-теги/пиксели — вообще не в скоупе этого скилла, даже как «дубли установки». Только CallRail-подобная подмена номеров.
- Бизнес-логика самого свопа (какой номер должен показываться для какого источника трафика/канала) — агент не эмулирует источник трафика, это делает трекинг-специалист.
- Соответствие конкретного номера конкретной странице/кампании — **без** явно переданного пользователем списка оригинальных номеров это не проверяется вообще (см. п.2).

## Что проверяется

### 1. Отработка свопа — техническая работоспособность (всегда, если скилл вызван)
- [ ] После загрузки страницы отображается валидный по формату номер (US-формат, см. `content-checks`).
- [ ] Скрипт свопа (например с домена `callrail.com`) загружается и выполняется без JS-ошибок в консоли (`playwright-cli console`).
- [ ] Связанный сетевой запрос (например `swap_session.json` и подобные, см. `playwright-cli requests`) не возвращает 4xx/5xx.

Это подтверждает, что механизм технически работает — не то, что показан «правильный» номер для этой страницы/канала.

### 2. Оригинальные номера в исходном коде (ТОЛЬКО если пользователь передал их для сверки)
- [ ] Если пользователь явно передал в `Сайты.txt` (`Комментарии:`) список оригинальных (не свопнутых) номеров — сверь их с тем, что реально в исходном коде страницы: Schema-разметка (JSON-LD `telephone`), серверно отрендеренный HTML — то есть то, что не подставлено JS-свопом поверх. Это важно для NAP-консистентности (Schema часто рендерится с оригинальным номером, а визуально подменяется скриптом уже в браузере).
- [ ] **Если пользователь не передал такой список — эту часть не выполняй вообще.** Не угадывай, какой номер «оригинальный», и не утверждай ни совпадение, ни расхождение без явных данных.

## Как оформлять находки
Находки из обоих пунктов — конкретные, проверяемые технические факты (JS-ошибка, 4xx/5xx, несовпадение с явно переданным пользователем номером), поэтому идут в **«Баги»** основного отчёта (см. CLAUDE.md, «Формат отчёта»), а не в «Рекомендации» — здесь нет места догадке о бизнес-логике трекинга, только проверяемые факты.

Если ничего не найдено — одна строка «CallRail: своп отрабатывает технически корректно» (+ «, сверка с оригинальными номерами не найдено расхождений» — если список был передан).
