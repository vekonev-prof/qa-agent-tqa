# Сравнение с Figma-макетом

## Условие вызова
Только если одновременно: (1) для сайта/страницы передана ссылка на Figma в `Сайты.txt`, и (2) `visual-checks` уже нашёл конкретное подозрение на расхождение. Не вызывай для всех страниц подряд и не вызывай, если Figma-ссылка не передана.

## Входные параметры
- URL страницы, где найдена проблема.
- Ссылка на Figma-макет (и, если известен, конкретный frame/node в макете, соответствующий проблемной секции).

## Алгоритм (сокращённый, только проблемная секция)
1. Извлеки file key (и node-id, если он есть в ссылке) из URL Figma.
2. Запроси у Figma MCP данные только по нужному узлу/фрейму, не по всему файлу — посмотри в описании доступных инструментов MCP, какой из них принимает node-id и ограничивает выдачу конкретным узлом, и используй его вместо запроса всего файла.
3. Если для сравнения нужен snapshot сайта — используй `playwright-cli snapshot --depth=4`, не полный snapshot.
4. Сравнивай структуру и ключевые визуальные параметры (наличие секции, порядок, число колонок, цвет) — НЕ pixel-perfect, и только для секции с подозрением на баг.
5. Если размеры элемента в CLI отличаются от Figma больше чем на 20% — сделай скриншот только этого элемента (не всей страницы, сохрани в `screenshots/{домен}/`) и передай в Vision вместе с соответствующим фрагментом макета для финального решения.

## Что не делать
- Не загружай Figma-файл целиком.
- Не сравнивай страницы/секции, где `visual-checks` не нашёл проблем.

## Формат результата
- **Статус:** «Макет загружен, расхождений нет» / «Макет загружен, найдены расхождения» / «Макет не загружен (ошибка)».
- Если есть расхождения — по каждой: страница, секция, краткое описание проблемы.

**Пример:**
```
Сравнение с Figma: макет загружен.
Расхождения:
- /about, секция «Преимущества»: в макете 3 колонки, на сайте — 4.
- /contact: цвет CTA-кнопки на сайте красный, в макете — синий.
```
