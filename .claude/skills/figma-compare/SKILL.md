# Сравнение сайта с Figma-макетом

**Внимание:** Этот Skill вызывается ТОЛЬКО если visual-checks обнаружил расхождения. НЕ вызывай для каждой страницы по умолчанию.

## Входные параметры

- **URL сайта** – страница, на которой visual-checks нашёл проблемы.
- **Ссылка на Figma** – передаётся пользователем в файле `Сайты.txt`.

**Условие вызова:** только если есть подозрение на расхождение с макетом.

---

## Алгоритм работы (сокращённый)

1. **Извлеки ID файла** из ссылки.
2. **Получи структуру макета** через MCP (только для конкретной страницы, а не всего сайта).
2.5. Если для сравнения нужен snapshot страницы, используй `playwright-cli snapshot --depth=4` вместо полного snapshot – это снизит расход токенов.
3. **Сравни структуру** (НЕ pixel-perfect) только по тем секциям, где visual-checks нашёл проблемы.
4. **Фиксируй ТОЛЬКО серьёзные расхождения** – отсутствие секции, порядок, цветовая гамма.
5. **Верни результат** для включения в отчёт.

**Что НЕ делать:**
- Не загружай весь макет целиком – используй `get_selection` только для нужного фрейма.
- Не сравнивай страницы, где visual-checks не нашёл проблем.

---

## Формат результата

Верни структурированный текст для включения в общий отчёт:

- **Статус:** «Макет загружен, расхождений нет» / «Макет загружен, найдены расхождения» / «Макет не загружен (ошибка)».

- Если есть расхождения – перечисли их с указанием:
  - страницы (URL);
  - секции (например, «герой-блок», «форма»);
  - описание проблемы (кратко).

**Пример результата:**
Сравнение с Figma: макет загружен.
Расхождения:

Секция «Преимущества» в макете имеет 3 колонки, на сайте – 4 колонки (страница /about).

Цвет кнопки CTA на сайте – красный, в макете – синий (страница /contact).

---

## Использование внутри агента

Этот Skill вызывается только когда пользователь явно передал ссылку на Figma.  
Результат включается в основной отчёт агента в раздел «Сравнение с Figma».
