# Сверка с Figma-макетом

Цель сверки — «сайт не сломан относительно макета», а не pixel-perfect. Поэтому НЕ сравниваются: тексты (в макетах часто заглушки; орфографию и lorem ловит `content-checks`), точные размеры шрифтов и отступов, зазоры, пиксели. Никаких процентных порогов размеров нет.

## Режимы
- **Базовый** — по умолчанию, если для страницы передана Figma-ссылка: **А** (блоки: наличие и порядок) + **Б** (подробное сравнение секции, по которой `visual-checks` нашёл подозрение).
- **Полный** — только если в `Сайты.txt` есть строка `Сверка с макетом: полная` (одна на весь файл; действует для всех страниц, у которых есть Figma-ссылка): базовый + **В** (палитра и шрифты страницы против Style Guide) + **Г** (подробное сравнение опорного набора блоков без ожидания подозрения). Дороже по токенам и по вызовам Figma — включается только по запросу пользователя.

## Условие вызова
Для сайта/страницы передана ссылка на Figma в `Сайты.txt`. Для лендинга из блока `Лендинги:` без собственной Figma-ссылки скилл не вызывается — макет основного сайта на лендинги не наследуется. **Источники ссылок:** главная — ссылка во втором поле строки сайта; каждый другой шаблон — своя ссылка из блока `Макеты:` (по классификации шаблонов Шага 1: страница шаблона получает ссылку своего типа); лендинг — своя ссылка через `|`. Макеты шаблонов обычно лежат в разных файлах проекта Figma, а Figma MCP видит только тот файл, ссылку на который ему передали; список остальных файлов проекта недоступен, поэтому **шаблон без переданной ссылки не сверяется** (статус «макет шаблона не предоставлен»): не ищи его в других файлах и не подставляй кадр главной. **Figma MCP есть только у оркестратора** (у подагентов его нет): скилл выполняет оркестратор (или единственный агент). Подагент возвращает расхождения `visual-checks` (страница, разрешение, секция); страницу оркестратор открывает сам в сессии `<разрешение>-orch` (на закрытом DEV — с `state-load` или входом по Basic, см. CLAUDE.md, Шаг 2), скрипты запускает сам.

Выполняется на одной странице каждого шаблона, у которого есть кадр макета, на десктопе и на мобилке (на планшете — только если в макете есть планшетный кадр).

## Инструменты (все дешёвые, используй их, а не «в уме»)
- `node .claude/tools/figma-frames.js <файл-ответа> [--frame <id>]` — разбор большого ответа `get_metadata` (кадры страницы; блоки кадра по порядку с их заголовками).
- `playwright-cli --raw -s=<сессия> run-code --filename=.claude/tools/style-probe.js` — секции страницы сайта по порядку + реальные цвета/шрифты (после паузы ≥3 с; на десктопе и на мобилке).
- `node .claude/tools/color-delta.js A B` и `--palette "<цвета палитры>" <цвет> …` — расстояние между цветами (CIEDE2000) и цветовое семейство; вердикт `same` (игнорировать) / `shade` (оттенок того же цвета) / `different` (другой цвет). Границы — стартовые, подбираются пилотом. Цвета никогда не сравнивай на глаз.
- Figma MCP: `get_metadata` (без `nodeId` — список страниц файла; с `nodeId` страницы или кадра — метаданные), `get_design_context` (код блока с точными цветами, шрифтами `font-['Family:Weight']`, раскладкой; для выбора данных — `excludeScreenshot: true`, скриншот запрашивай только для спорных мест). **`get_variable_defs` не используй** — он требует выбранный слой в приложении Figma и по ссылке не работает.
- Перед ПЕРВЫМ `get_design_context` за прогон прочитай ресурс `skill://figma/figma-design-to-code/SKILL.md` (сервер `figma`) — этого требует сам инструмент; код по нему писать не нужно (нам нужны только данные), а в вызове передавай `skillNames: "resource:figma-design-to-code"`.

## Подготовка (один раз за прогон, результат запоминай и не запрашивай повторно; тот же список используется на Шаге 1 CLAUDE.md)
1. Список страниц файла: `get_metadata` без `nodeId`. Обычно в файле агентства есть страница со страницами/шаблонами сайта (например `HP`) и страница `Style Guide`.
2. Метаданные нужной страницы: `get_metadata` с `nodeId` этой страницы. **Ответ может быть огромным (миллионы символов, реальный пример — 3,4 млн): его сохраняют в файл — целиком в контекст не читай никогда**, только `figma-frames.js`. Если ответ пришёл в контексте небольшим — читай его напрямую.
3. Основной кадр каждого разрешения (в файле много черновиков: `… - 1`, кадры «1…6», `refs`, варианты меню/hover, отдельные компоненты — их не бери):
   - desktop: ширина 1200–1999 (обычно 1440 или 1920), имя кадра совпадает с названием шаблона/страницы (`HP`) без пометок; если подходящих несколько — самый высокий;
   - mobile: ширина 300–699 и в имени `mobile`; tablet: ширина 700–1199.
   Разрешение определяй по ШИРИНЕ кадра, а не по названию. Имя шаблона в макете и на сайте может отличаться (`HP` = главная): сопоставляй по смыслу страницы.
4. Если для шаблона не передано ссылки или в переданном файле нет подходящего кадра — статус «макет шаблона не предоставлен»; если для разрешения нет — «макет для [разрешение] не предоставлен» (не придумывай и не экстраполируй, кадр другого разрешения за эквивалент не считай). В этих случаях остаются только проверки, не требующие кадра (В в полном режиме).
5. Только для полного режима: палитра из Style Guide. Кадр с названием `Colors…` страницы `Style Guide` (найти через `figma-frames.js`) → `get_design_context` с `excludeScreenshot: true`. Палитра — в конце ответа, строка `These styles are contained in the design: bg: #0A0A0A, gold: #C2BE7C, …`; если её нет — hex из классов `bg-[#…]` рядом с подписями цветов. Шрифты берутся из кода блоков (`font-['Roboto:Bold']`) и, если в Style Guide есть кадр `Typography…`, из его подписей (этот кадр большой — запрашивай его только если шрифты не удалось определить из блоков).

## А. Блоки: наличие и порядок (базовый и полный режимы) — обязательно находить, если блок есть в макете и пропал на сайте
1. Блоки макета: `figma-frames.js <файл> --frame <id основного кадра>` → блоки сверху вниз (имя, заголовки-тексты).
2. Секции сайта: `style-probe.js` на этом же разрешении → `sections` по порядку.
3. Для каждого блока макета найди пару на сайте, в таком порядке приоритета:
   (1) заголовок секции совпадает по смыслу (тексты-заглушки не считаются);
   (2) тип блока: меню/шапка, подвал, форма (`form`), карта (`map`), отзывы (`reviews`), CTA (блок с заметной кнопкой), первый экран (H1). Тип считается совпадением ТОЛЬКО если блок этого типа в макете и на сайте один. Если на сайте два блока одного типа, а в макете один (или наоборот), пару не угадывай: отметь блок как «пара неоднозначна»;
   (3) порядок — только как опора между уже найденными парами: блок без заголовка и без типа получает пару, если между двумя соседними найденными парами на сайте ровно одна непарная секция. Иначе блок остаётся «пара неоднозначна».
   Имена блоков в макете авторские («trasts», «case») — по имени сопоставлять нельзя.
4. Итог:
   - блок макета без пары на сайте → **находка «блок отсутствует»**. Перед выводом докажи отсутствие: перепроверь `find` по ключевому слову заголовка и `snapshot --depth=4` секции, где блок должен быть; блок мог быть скрыт по условию — тогда сверяй с кадром того же разрешения;
   - блок макета с неоднозначной парой → не находка, а пункт «Рекомендации для ручной проверки» (какой блок макета, какие секции сайта кандидаты);
   - блоки есть, но порядок другой → находка «порядок блоков»; порядок сравнивай только по парным блокам, лишние секции сайта в сравнении порядка не участвуют; перечисли фактический порядок на сайте и порядок в макете;
   - секция сайта без пары в макете → **«лишняя секция»**. Лишними не считаются: шапка, подвал, cookie-баннер, чат-виджет, попапы, sticky-элементы.
     • Находка `[Visual]` 🟨, если одновременно: (а) макет этого шаблона и разрешения предоставлен; (б) каждый блок макета нашёл пару на сайте (нет отсутствующих и неоднозначных); (в) секция не подошла ни по заголовку, ни по типу. Формулируй как «в макете такой секции нет», не как «не должно быть» (макет мог устареть).
     • Иначе (не выполнено (а) или (б), либо секция похожа на сторонний виджет) — «Рекомендации для ручной проверки».
   - лишние элементы внутри блока (кнопка, картинка) не проверяются; число колонок/элементов в ряду сравнивается только в Б и Г.
5. Доказательство — два списка дословно: блоки макета (`id`, имя, заголовок) и секции сайта (`tag`, `heading`, `y`); для «лишней секции» выдели её в списке сайта.

## Б. Секция с подозрением (базовый и полный режимы)
Только если `visual-checks` нашёл конкретное подозрение на этой странице и разрешении. Найди блок макета для секции (как в А, п.3) → `get_design_context` этого блока (со скриншотом только при необходимости) → сравни:
- число колонок / элементов в ряду и порядок элементов внутри блока;
- цвета фона, главной кнопки, заголовка (цвет в макете — из кода блока; на сайте — из `style-probe.js`/`eval`; сравнение — через `color-delta.js`);
- семейство шрифта (не размер);
- наличие ключевых изображений.
Скриншот элемента + фрагмент макета отдавай в Vision только если числовых данных не хватает для решения.

## В. Палитра и шрифты страницы (только полный режим)
1. Цвета сайта: из `style-probe.js` — `palette.backgrounds`, `palette.texts`, `palette.buttonBgs`, плюс `buttons`, `h1`, `header`, `footer`. Одной командой сравни ВСЕ уникальные цвета с палитрой Style Guide: `node .claude/tools/color-delta.js --palette "#0A0A0A,#C2BE7C,…" "rgb(…)" …`.
2. Вердикт по цвету: `same` — ничего; `shade` — оттенок того же цвета, находкой считай только если это фон крупного блока, главная кнопка или заголовок; `different` (другое семейство: зелёный вместо жёлтого, или далеко от любого цвета палитры) — находка.
3. Шрифты: `fonts` из `style-probe.js` против семейств из макета. Сравнивай нормализованно (без пробелов и регистра, без суффиксов веса: `SourceSansProRegular` и `Source Sans Pro` — одно и то же). Семейство, которого нет в макете, — находка; сомневаешься (подстановка, системный шрифт вместо веб-шрифта) — в «Рекомендации для ручной проверки».

## Г. Опорный набор блоков (только полный режим)
5–7 блоков, которые есть в макете: шапка/меню, первый экран (Hero), главная кнопка/CTA-блок, один типовой контентный блок, форма (если есть), подвал. По каждому — как Б (`get_design_context` блока → колонки, порядок, цвета через `color-delta.js`, семейство шрифта, ключевые изображения), не дожидаясь подозрения. Один вызов на блок, результат запоминай.

## Серьёзность (для отчёта; тег `[Visual]`)
- блок из макета отсутствует на сайте — 🟥; порядок блоков отличается — 🟨; лишняя секция на сайте (нет в макете) — 🟨;
- цвет `different` у фона блока, главной кнопки или заголовка — 🟨; `shade` — 🟩;
- другое семейство шрифта — 🟨; пропала ключевая картинка блока или другое число колонок — 🟨.

## Экономия и ограничения
- Вызовы Figma делает только оркестратор; список страниц, метаданные страницы, палитру и блоки запрашивай один раз за прогон и запоминай.
- Лимит Figma MCP зависит от тарифа и места (Full/Dev на платном плане — порядка 200 вызовов в день; место View — считаные вызовы в месяц). Ошибка лимита или доступа → статус «Макет не загружен (ошибка)» с причиной; остальные проверки страницы не блокируются.
- `style-probe.js` и `figma-frames.js` — сборщики фактов, не судьи: решения принимаешь ты по правилам выше.

## Формат результата
- **Режим:** базовый / полный.
- **Таблица «что с чем сравнивалось»** (обязательна в отчёте, «Технические детали»): по одной строке на КАЖДУЮ проверенную страницу и разрешение, включая те, для которых макета нет: страница сайта (шаблон) · макет (файл · страница Figma · имя кадра и его id) · устройство и ширина кадра макета (из размеров кадра: десктоп 1440, мобилка 375…) · разрешение проверки на сайте (десктоп 1920×1080, мобилка 390×844, планшет 768×1024) · статус (сверено, число расхождений, неоднозначных пар: N, лишних секций: N / расхождений нет / макет шаблона не предоставлен / макет для разрешения не предоставлен / кадр не опознан / ошибка доступа или лимита). Так видно, каким макетам какая страница и на каком устройстве соответствовала.
- **Статус:** «Макет загружен, расхождений нет» / «Макет загружен, найдены расхождения» / «Макет не загружен (ошибка)» / «Макет загружен, но нужный кадр не опознан — сравнение не выполнено» / «Макет для этого шаблона/разрешения не предоставлен».
- По каждому расхождению: страница, разрешение, блок, что не совпало и данные (списки блоков; цвета сайта и палитры с ΔE; семейства шрифтов). Оформляется пунктом основного списка с тегом `[Visual]` (доказательство — дословные данные из инструментов, скриншот — если он нужен для понимания).

**Пример:**
```
Сравнение с Figma (режим: базовый): макет загружен.
Расхождения:
- / (десктоп): блок «Areas We Serve» (карта, кадр HP 4860:978) отсутствует на сайте; секции сайта: HEADER, Hero, Practice Areas, CTA, team, form, FOOTER.
- / (мобилка): порядок блоков — в макете CTA перед Practice Areas, на сайте после.
```
