# Контентные проверки

Ты проверяешь качество контента на странице сайта.

**Источник фактов о DOM:** факты (`<head>`, заголовки, JSON-LD, ссылки, картинки, тексты, раскладка, формы) сначала возьми из результата `page-audit.js` (см. CLAUDE.md, Шаг 2.1); отдельные `eval`/`find` — только для того, чего там нет, или для перепроверки конкретной находки.

## Чек-лист

### 1. Тексты
- [ ] Нет lorem ipsum и текста-заглушки ("текст", "заголовок", "Lorem ipsum dolor...") — из page-audit (`text.lorem`, `text.placeholders`).
- [ ] Нет кириллицы, если сайт англоязычный (кроме официальной русскоязычной версии, если она предусмотрена) — из page-audit (`text.cyrillicWords`, `text.cyrillicSample`).
- [ ] Мультиязычность: на второй языковой версии (обычно её ты видишь при проверке в мобильном разрешении — см. CLAUDE.md, Шаг 2, «Мультиязычные сайты») весь контент, меню и футер переведены полностью — не должно оставаться непереведённых фрагментов на языке оригинала. Найденный непереведённый блок — это, скорее всего, X-site баг (блок переиспользуется в других шаблонах), отметь это в отчёте.

### 2. Картинки
- [ ] Нет картинок, не соответствующих тематике/географии сайта — в частности "славянизированных" стоковых фото (постсоветские дворы, техника, узнаваемо не-американский антураж) на сайтах для клиентов в США.
- [ ] Формат современный для веба: фото — AVIF/WebP предпочтительно (JPEG/PNG допустимы как запасной вариант); UI-иконки — SVG (favicon/apple-touch-icon — исключение, там обязателен PNG, см. `visual-checks`). Форматы — из page-audit (`images.formats`).
- [ ] Размер файла — ориентир ~150 Кб на изображение (внутренний стандарт агентства); от ~300 Кб (вдвое больше ориентира) — однозначный повод для оптимизации, фиксируй как баг. Серьёзность (`[Visual]`): 150–300 Кб — 🟩 Minor, и только если массово (≥3 картинок на странице или ≥2 страниц одного шаблона); от 300 Кб — 🟨 Major. Вес — из page-audit (`images.heavyOver150KB`).
- [ ] Отображаемое разрешение соответствует размеру контейнера: картинка не увеличена сверх натурального размера (не размыта); из page-audit — `images.oversized` (наоборот, слишком тяжёлая для контейнера). Искажение пропорций (сплющена/растянута, круг стал эллипсом) — не здесь, это зона `visual-glance`.
- [ ] alt-теги присутствуют и описательны (page-audit: `images.altMissing`, `images.altEmpty`) (не пустые, не техническое имя файла типа "image123.jpg", отражают содержание картинки). Если проблема массовая (много страниц/картинок) — зафиксируй одной строкой со ссылкой на список, не описывай каждую картинку отдельно.
- [ ] Нет карточек/секций с отсутствующей картинкой там, где по дизайну она должна быть (пустой слот, битая иконка вместо изображения) — из page-audit (`images.broken`); 404 на видимой картинке — `[Visual]` 🟥. **Исключение — `.avif`, битая только в WebKit (планшет/мобилка): это ограничение инструмента, не находка** (`page-audit`: `images.brokenAvif` при `images.engine: webkit-or-other`); порядок проверки в Chromium и запись в «Рекомендации» — CLAUDE.md, «Обработка ошибок», пункт «AVIF в WebKit».

### 3. US-форматы (для сайтов клиентов в США)
- [ ] **Дата** — месяц указан раньше дня (US-порядок), в любом из двух видов: цифрами (`03/05/2026`) или словом (`March 5, 2026`). Баг: день раньше месяца (`05/03/2026` — европейский порядок, `5 March 2026`), или ISO (`2026-03-05`) в видимом тексте страницы — ISO допустим только в машиночитаемых атрибутах (`datetime=...`), не как то, что видит посетитель.
- [ ] **Телефон (видимый текст)** — `(XXX) XXX-XXXX`, без `+1` в видимом тексте (page-audit: `text.phonesVisible[].usFormat`/`plus1`) — так агентство обычно показывает номер для американской аудитории. `+1` ожидается только в `tel:`-href (см. `technical-checks` §4) — это отдельный, машиночитаемый формат, не видимый текст, противоречия с этим пунктом нет.
- [ ] **Адрес** — перед ZIP должен стоять двухбуквенный код штата (`CA`, `NY` и т.п.), не полное название (`California`); ZIP — 5 цифр, опционально `+4` (`12345` или `12345-6789`). Ожидаемый вид: `Город, XX 12345`. Баг — полное название штата вместо кода, или ZIP не в этом формате.
- [ ] Валюта: символ $ (USD), не € и не голое число без знака валюты.
- [ ] Единицы измерения: `mi`/`mile(s)`, `ft`/`foot`/`feet`, `in`/`inch(es)` — ОК; `km`/`kilometer(s)`, `m`/`meter(s)`, `cm` в контексте расстояния/размера — баг.

### 4. Meta-теги
**Только на десктопе (см. CLAUDE.md, Шаг 2) — данные из `<head>`, не зависят от вьюпорта; не повторяй эту секцию при вызове на мобильном снапшоте той же страницы.** Значения — из page-audit (`head.title`, `head.titleLen`, `head.description`, `head.descriptionLen`).
- [ ] meta title уникален для каждой страницы, отражает её содержание, длина ~50–60 символов. (Отсутствие/пустой/дефолтный `<title>` — `[Visual]`, см. `visual-checks` §3; длина и уникальность — `[SEO]`.)
- [ ] meta description уникален, отражает содержание, длина ~150–160 символов.
- [ ] meta description не пустой и не дефолтный (дефолтный вид — например "Home - WordPress").
- [ ] meta description не содержит телефонный номер — номера меняются (свопы для трекинга), в meta он быстро устаревает и не обновляется вместе с сайтом.

### 5. Виджеты отзывов / социального доказательства (если есть на странице)
- [ ] Если на странице есть визуальный блок сторонних отзывов (Google reviews карусель, Elfsight, Trustpilot и подобные виджеты) — убедись, что он реально показывает контент (текст отзывов/рейтинг/аватары), а не пустой контейнер, заглушку или бесконечный лоадер.
- [ ] Проверяй только после полной прогрузки страницы — такие виджеты часто асинхронные (аналогично Schema, см. `technical-checks` §9). Не фиксируй «не грузится» сразу после открытия страницы — подожди отрисовки и перепроверь.
- [ ] Если виджет пуст/не загрузился даже после ожидания — баг: «виджет отзывов на странице не отображает контент».

### 6. Open Graph и Twitter Card
**Только на десктопе (см. CLAUDE.md, Шаг 2) — данные из `<head>`, не зависят от вьюпорта; не повторяй эту секцию при вызове на мобильном снапшоте той же страницы.** Набор тегов — из page-audit (`head.og`, `head.twitter`); URL `og:image` и его размер проверяй отдельно.
- [ ] `og:title`, `og:description`, `og:image` (URL не 404, размер около стандартного для превью в соцсетях — ~1200×630, не просто логотип/заглушка), `og:url` (канонический URL).
- [ ] `twitter:card`, `twitter:title`, `twitter:description`, `twitter:image` — присутствуют хотя бы в базовом виде, чтобы превью корректно рендерилось в X/Twitter, LinkedIn, iMessage и подобных.

На мультиязычных сайтах meta/OG проверяются только на основной языковой версии (десктоп).

## Возвращаемый результат
- **ADA не проверяется и не упоминается:** `aria-label`, контраст, альтернативные тексты для скринридеров и прочая доступность — не отмечай и не описывай нигде в отчёте, в том числе в «Рекомендациях» (единственное исключение — общая строка «ADA агентом не проверяется», см. CLAUDE.md).
- Список найденных проблем с указанием страницы и (если применимо) языковой версии.
- Тег типа для отчёта: тексты/картинки/US-форматы — `[Visual]`; meta/Open Graph/Twitter Card — `[SEO]`; виджет отзывов — `[Interactive]` (см. CLAUDE.md, «Формат отчёта»).
- Если проблем нет — «Контентных проблем не обнаружено».
