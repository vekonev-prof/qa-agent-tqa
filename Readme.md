# QA Agent for TQA Checks

AI-агент на базе Claude Code CLI и Playwright CLI для автоматической TQA-проверки сайтов (визуал, контент, техника, формы/калькуляторы, Figma) перед презентацией dev-сайта клиенту — и для повторных проверок уже запущенных (LIVE) сайтов.

## Какую задачу решает

TQA-инженер вручную прогоняет один и тот же чек-лист на каждом новом сайте: визуальный QA, контент, техника/SEO, базовый ADA, сверка с Figma, тест форм и калькуляторов. Это долго и легко что-то пропустить. Агент берёт список сайтов из `Сайты.txt`, сам открывает нужные страницы в двух разрешениях, прогоняет по ним весь чек-лист и отдаёт готовый структурированный отчёт с багами — с приоритетом «блокирует презентацию клиенту / нет», а не абстрактным «критично/некритично».

## Что именно проверяет

- **Визуал (`visual-checks`):** UI/UX на десктопе и мобилке, favicon/apple-touch-icon, `<title>`, H1 и иерархия заголовков, главное меню (все режимы, top bar, дубли в коде), breadcrumbs, формы (визуально + атрибуты полей), аккордеоны/FAQ, блок Google Maps.
- **Контент (`content-checks`):** lorem ipsum/заглушки, кириллица и «славянизированные» картинки на англоязычном сайте, мультиязычность (`/es` и т.п.), форматы и вес картинок, alt-теги, US-форматы (дата/телефон/адрес/валюта/единицы измерения), meta title/description, Open Graph и Twitter Card.
- **Техника (`technical-checks`):** ошибки в консоли, битые запросы (404), редиректы 3xx, sitemap.xml и noindex на служебных страницах, пустые/битые ссылки и перелинковка (в том числе «ссылка ведёт не на тот объект»), атрибуты `rel`/`target`, консистентность телефонного номера по сайту (свопы для трекинга — легитимны только на LIVE, на DEV номер должен быть один и тот же везде), Schema-разметка в формате JSON-LD (LocalBusiness/LegalService, Organization, Product, Article/BlogPosting, BreadcrumbList, ProfilePage, FAQPage — с проверкой обязательных для Google полей по каждому типу и без дублей), базовый ADA (контраст, семантика, ARIA, клавиатура, focus, клавиатурные ловушки в аккордеонах).
- **Формы и калькуляторы:** реальный сабмит критических форм (главная контактная форма, hero/quick-quote, функциональные калькуляторы), максимум 2–3 попытки на уникальный шаблон — сначала граничный/невалидный кейс (должен блокироваться), потом валидный (должен пройти), при необходимости точечная проверка. Заранее строится карта обязательности полей (визуал vs фактический `required`) и ищутся противоречия между ними. Безопасные тестовые данные — не визуальная имитация, а настоящая проверка, что сабмит проходит и калькулятор считает адекватно.
- **Figma (`figma-compare`):** точечная сверка конкретной секции с макетом — только если по ней уже найдено визуальное расхождение и макет передан.

## Из чего состоит агент

- **Главный промпт — [`.claude/CLAUDE.md`](.claude/CLAUDE.md).** Это системная инструкция, которую Claude Code загружает автоматически при каждом запуске из этой папки. Она не проверяет ничего сама — это оркестратор: описывает формат `Сайты.txt`, алгоритм по шагам (выбор страниц → открытие → вызов Skills → сабмит форм → скриншоты → Figma → правки на перепроверку), правило сабмита форм/калькуляторов (какие тестовые данные использовать, что можно, а что нет), формат итогового отчёта и что делать при ошибках.
- **Skills — `.claude/skills/*/SKILL.md`.** Каждый skill — это отдельный «модуль» чек-листа, который агент вызывает по ходу работы; Claude Code подгружает его содержимое только когда он реально нужен (экономия токенов):
  - `visual-checks`, `content-checks`, `technical-checks` — три группы проверок выше.
  - `figma-compare` — сверка с макетом, вызывается только при подозрении на расхождение.
  - `playwright-cli` — техническая справка по командам браузерной автоматизации (открытие страниц, snapshot, click, eval и т.п.), сгенерированная самим Playwright CLI — ей пользуются остальные skills, чтобы управлять браузером.

Ничего кроме этих файлов агенту для работы не нужно — весь чек-лист и вся логика живут в `.claude/`.

## Что передавать в `Сайты.txt`

Один сайт (основной сайт клиента **или** лендинг на суб-домене) на строку:

```
URL | ссылка_на_Figma | DEV
```

- **URL** — обязателен.
- **Ссылка на Figma** — опциональна. У основного сайта и у каждого лендинга может быть свой макет.
- **Окружение `DEV`/`LIVE`** — опционально, но желательно указывать: на `LIVE` номер телефона может быть легитимно подменён (своп для колл-трекинга) и отличаться от Figma/DEV; на `DEV` такого быть не должно. Без этой пометки агент не сможет отличить легитимный своп от реальной ошибки в номере. **На возможность сабмитить формы окружение не влияет.**

Плюс два опциональных блока в конце файла:

```
Правки:
- [что перепроверить, что было исправлено]

Комментарии:
- [пожелания клиента/ПМа: специфика проекта, ТЗ на логику калькулятора, тип бизнеса и т.п.]
```

Пример полного файла:
```
https://client-site.com | https://figma.com/file/xxxx/Main | DEV
https://landing.client-site.com | https://figma.com/file/yyyy/Landing | DEV

Правки:
- [contact form] сабмит не работал — перепроверить

Комментарии:
- Проект — moving company, проверить поля адреса и автоподбор
- ТЗ на калькулятор: cost = base_rate + distance_miles * per_mile_rate
```

## 🚀 Быстрый старт (для человека, который раньше это не запускал)

### 1. Установите необходимое ПО
- **Node.js 18+** – [скачать](https://nodejs.org/)
- **Git Bash** (для Windows) – [скачать](https://git-scm.com/downloads/win)
- **Аккаунт Claude** – [зарегистрироваться](https://claude.ai/)
- **Аккаунт Figma** (опционально, если нужна сверка с макетами)

### 2. Установите Claude Code CLI
```bash
npm install -g @anthropic-ai/claude-code
```
Проверьте установку:
```bash
claude --version
```

### 3. Установите Playwright CLI и браузеры
```bash
npm install -g @playwright/cli@latest
playwright-cli install-browser
```

### 4. Авторизуйтесь в Claude Code
```bash
claude
```
Следуйте инструкциям в терминале: откроется браузер, где нужно войти в аккаунт Claude.

### 5. Клонируйте репозиторий
```bash
git clone https://github.com/vekonev-prof/qa-agent-tqa.git
cd qa-agent-tqa
```

### 6. Установите Skill для Playwright CLI (обязательно!)
```bash
playwright-cli install --skills
```
Эта команда создаст файл `.claude/skills/playwright-cli/SKILL.md` для интеграции Playwright CLI с Claude Code.

### 7. Настройте Figma MCP (опционально)
Если планируете сверять с макетами:
```bash
claude mcp add --transport http figma https://mcp.figma.com/mcp
```
При первом запуске `claude` откроется браузер для авторизации в Figma.

### 8. Подготовьте `Сайты.txt`
Создайте файл `Сайты.txt` в корне проекта в формате, описанном выше в разделе «Что передавать в `Сайты.txt`».

### 9. Запустите агента
```bash
claude -p "Проверь сайты из файла Сайты.txt" --output-format text | tee report.txt
```
Вывод будет показан в терминале и одновременно сохранён в файл `report.txt`.
Скриншоты багов сохраняются в папку `screenshots/`, служебные снапшоты страниц (yml) — в `.playwright-cli/`.

### 10. Посмотрите отчёт
Откройте `report.txt` — там структурированный список багов по приоритету «блокирует презентацию клиенту / не блокирует / ADA», плюс раздел по перепроверенным правкам и рекомендации для ручной проверки (например, подтвердить в CRM/почте, что тестовые сабмиты форм дошли).

## 🧠 Как это работает

| Что делает агент | Подробнее |
|---|---|
| Выбор страниц | Проверяет только 1–2 страницы из каждого типа (шаблона) – не ходит по всему сайту |
| Проверки | Три группы Skills: `visual-checks`, `content-checks`, `technical-checks` — вызываются на каждой отобранной странице |
| Формы и калькуляторы | Реально сабмитит только критические формы (максимум 2–3 раза на уникальный шаблон: граничный кейс → валидный кейс → точечная проверка), с безопасными идентифицируемыми тестовыми данными — не спамит и не трогает второстепенные формы |
| Figma | Сравнивает с макетом только при найденных расхождениях (экономия токенов) |
| Скриншоты | Делает только при обнаружении проблем, сохраняет в `screenshots/` – не тратит токены на успешные шаги |
| Оптимизация токенов | `snapshot --depth=4` и `find` вместо полного accessibility tree, группировка массовых багов в одну строку отчёта |
| Отчёт | Структурированный список багов: блокирует презентацию клиенту / MAJOR / MINOR / ADA, плюс перепроверка правок и рекомендации для ручной проверки |

## 📌 Важно
- Агент сабмитит формы/калькуляторы — но только критические (максимум 2–3 раза на уникальный шаблон), безопасными тестовыми данными (см. `.claude/CLAUDE.md`, Шаг 3.1), никогда не массово.
- Агент не входит в админку/CMS и не может сам проверить, дошло ли письмо с формы — это всегда остаётся ручной проверкой в отчёте.
- Агент не ходит по всему сайту – выбирает 1–2 страницы из каждого типа (экономия токенов).
- Для работы с Figma нужен Pro-аккаунт (или токен доступа).
- Устойчив к типовым сбоям: сайт под паролем без доступа, антибот-защита/капча (в т.ч. при попытке сабмита формы), недоступный Figma MCP или упавшая браузерная сессия не останавливают весь прогон — фиксируются в отчёте и проверка идёт дальше (полный список — `.claude/CLAUDE.md`, раздел «Обработка ошибок»).
